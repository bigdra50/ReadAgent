# 0004. Phase 1 の実行形態をローカル Node サーバー + ブラウザにする

- **Status**: Accepted
- **Date**: 2026-08-10

## Context

要件 2 は「第1優先はローカル完結、将来はWebサーバー化も検討可能な設計」としている。
実行形態の候補は Electron / Tauri / ローカルサーバー + ブラウザ の3つだった。

判断を決めたのは、軽さや見た目ではなく次の3点である。

**Claude Agent SDK は Node プロセスを要求する。**
`@anthropic-ai/claude-agent-sdk`（TS版）は Node 上で動き、`claude` CLI をサブプロセスとして
起動して通信する。さらに要件 3.3 の「エージェントがカスタムツール経由でノートを更新する」は、
SDK のインプロセス MCP ツールで実装するのが素直である。
このため Tauri を選んでも「Node が要らない」構成にはならず、Node サイドカーの同梱か、
Rust からの CLI 直叩き（＝SDK の再実装、インプロセスツールの喪失）のどちらかを迫られる。
Tauri の主要な利点である配布サイズの優位は、ここでほぼ相殺される。

**webview のエンジン差が、選択位置の精度に直接効く。**
Tauri は OS の webview を使う（macOS: WKWebView / Linux: WebKitGTK / Windows: WebView2）。
pdf.js のテキストレイヤは DOM の Selection / Range API に乗るため、エンジンが変われば
選択範囲の取得結果も変わりうる。これは要件 3.1 の位置情報と、要件 3.3 の双方向リンクに直撃する。

**シェル系はサーバー化と地続きにならない。**
Electron / Tauri はアプリの内側に閉じるため、要件 2 の後半（Webサーバー化）へ進むときに
シェルごと捨てることになる。ローカルサーバー構成はそのまま延長線上にある。

## Decision

Phase 1 は **ローカルで動く Node サーバー + ブラウザ**で実装する。
UI は Vite でビルドし、サーバーは localhost にのみバインドする。
Claude Agent SDK とカスタムツールはこの Node プロセス内で動かす。

Electron / Tauri によるデスクトップシェルは **Phase 3 以降に再評価する**。
今は採用も却下もせず、判断を遅らせる。ADR-0003 でコアを純粋に保っている限り、
シェルを被せる差分は UI とプロセス境界に収まるため、遅らせるコストは小さい。

PDF は pdf.js（`pdfjs-dist`）でテキスト抽出とテキストレイヤ描画を行う。

## Consequences

- Agent SDK・インプロセスのカスタムツール・ストリーミングが、追加の仕掛けなしに書ける
- 開発中のブラウザを Chromium に固定でき、pdf.js のテキストレイヤ挙動を1エンジンで検証できる。
  未決定の「選択箇所の永続的な位置指定」に、エンジン差という変数を持ち込まずに取り組める
- TypeScript だけで完結する。Rust とパッケージングのコストを MVP の段階で払わない
- 要件 2 後半のWebサーバー化へは、認証と配信経路を足すだけで進める

払うコスト:

- **デスクトップアプリの体験は当面ない。** 起動はコマンド、UI はブラウザのタブになる。
  ファイル関連付け、ネイティブメニュー、ウィンドウ状態の復元は Phase 3 以降まで得られない
- ポート衝突とブラウザ自動起動の面倒を自分で見る必要がある
- localhost バインドかつ認証なしで始めるため、**同一マシン上の他プロセスからは到達できる**。
  ローカル完結の前提を外す（LAN 公開・サーバー化）時点で、認証を必ず入れること
- シェルへ移行する際は、UI とプロセス境界の再設計が必要になる。この判断を遅らせた分の先送りである

## Alternatives considered

- **Electron** — Node がメインプロセスにあり Agent SDK は素直に動く。Chromium 固定で pdf.js の
  挙動も確定的。却下したのは、MVP に不要な配布重量と、asar 内から CLI サブプロセスを起動する際の
  癖を今の段階で抱え込むため。Phase 3 でシェルを被せる際の第一候補として残す
- **Tauri** — 配布サイズとメモリでは最有力。却下したのは、Node サイドカー同梱で利点が目減りし、
  webview のエンジン差が選択位置の設計に不確実性を持ち込み、さらに Rust のグルーコードを
  一人開発で保守することになるため。配布サイズが要件として立ち上がったら再評価する
