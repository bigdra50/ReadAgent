対象: $ARGUMENTS

@docs/requirements.md の該当箇所を読み、次の手順で進めてください。

1. **範囲を決める** — 1回のPRで完結する最小の縦割りスライスに切る。広げすぎたら、やらないことを明示して切り落とす。
2. **設計を1段落で書く** — どのパッケージに何を置くか。`packages/core` は UI / Claude Agent SDK / fs に依存させない。境界を跨ぐなら理由を述べる。
3. **失敗するテストを先に書く** — 振る舞いの仕様を書く。実装の内部構造を写経しない。
4. **通るまで実装する** — 要件にない一般化・抽象化を先回りして入れない。
5. **`pnpm run verify`** を通す。
6. **報告** — 何を作ったか、意図的にやらなかったこと、次のスライスの候補。

判断が割れる設計上の分岐に当たったら、勝手に決めずに選択肢と推奨案を提示して確認してください。
決めた結果が後から効いてくるものなら `docs/adr/` に記録します。
